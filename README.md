# TikTok Lead Hunter

Личный локальный инструмент для поиска лидов в TikTok: поиск роликов по хэштегам
и ключевым словам, отбор лидов, черновики ответов по spintax-шаблонам, учёт аккаунтов
и статистика. Работает на одном ПК, рассчитан на одного пользователя.

## Запуск

Нужен Python 3.11+ (при установке отметьте «Add python.exe to PATH»).

Проще всего дважды кликнуть `start.bat`: при первом запуске он сам всё установит
(несколько минут), потом откроет http://127.0.0.1:8000.

Вручную (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\uvicorn app.main:app --port 8000
```

Откройте http://127.0.0.1:8000 (документация API: `/docs`).

Прокси (необязательно) задаётся во вкладке **«Настройки»**. Подходят форматы `ip:порт`,
`ip:порт:логин:пароль`, `логин:пароль@ip:порт`. SOCKS5 с логином и паролем Chromium не поддерживает.

## Рабочий процесс

1. **Аккаунт-менеджер → Добавить аккаунт**: откроется отдельное окно авторизации.
   Вставьте `sessionid` / экспорт cookies либо выберите «Войти в браузере».
   Если отдельный `sessionid` отклоняется, перенесите все cookies TikTok:
   F12 → Network → обновите страницу → запрос к www.tiktok.com → Headers → Request Headers → Cookie.
   Проверка входа выполняется внутри страницы TikTok; отказ переноса не означает, что вход в исходном браузере тоже истёк.
   Выбирать существующий аккаунт и вводить username не нужно: программа получает имя
   от TikTok и добавляет аккаунт только после успешной проверки. Первый подключённый
   аккаунт становится аккаунтом поиска по умолчанию. При ошибке пустая запись не создаётся.
2. **Наборы текстов**: создайте тематический набор и добавьте отдельные варианты.
   Каждый вариант поддерживает многострочный текст, `{Привет|Добрый день}`,
   вложенные варианты, `[author]` и `[query]`. Редактирование набора не меняет
   уже подготовленные комментарии.
3. **Аккаунт-менеджер → Настроить** в строке нужного аккаунта: вкладка «Наборы текстов»
   позволяет назначить один или несколько наборов. Один набор доступен нескольким аккаунтам.
4. В строке аккаунта показаны статус сессии, время проверки и кнопка «Проверить».
   «Проверить все сессии» и действие для выбранных аккаунтов запускают проверки группой.
   Если аккаунт занят, проверка ждёт его текущую задачу; повторные нажатия не создают дубликаты.
   Результат обновляется автоматически. Ошибка сети показывается отдельно от истёкшей сессии.
   Кнопка «Настроить» открывает одно окно с вкладками «Общее», «Наборы текстов» и «Сессия»:
   там находятся лимиты, прокси, наборы и переподключение. `0` означает отсутствие дневного лимита.
   Cookies хранятся отдельно в `data/session/account_<id>.json`. Повторное добавление
   подключённого аккаунта не заменяет его сессию; для замены используйте переподключение.
5. **Настройки**: выберите основной аккаунт поиска и число одновременных браузеров
   (по умолчанию 5 для новых настроек, от 1 до 8). В существующей установке проверьте
   этот параметр: для пяти одновременных окон нужно установить не менее 5.
   В форме поиска можно выбрать другой аккаунт для отдельной задачи.
   Быстрый поиск использует основной аккаунт. Индивидуальный прокси имеет приоритет
   над глобальным; новые настройки применяются при запуске следующей задачи.
6. **Поиск → Отбор роликов**: отметьте подходящие ролики. Нажмите «Подготовить
   комментарии» для отмеченных либо всех роликов «Подходят»; выберите аккаунты и наборы.
   Выбранные наборы применяются ко всем выбранным аккаунтам. Кнопка «Выбрать все
   по фильтру» учитывает текущие фильтры и все страницы. Окно проверяет повторы пар.
   Причины пропусков сгруппированы по аккаунтам; готовые тексты доступны для просмотра.
   Для каждого аккаунта под каждым роликом готовится один комментарий.
7. Просмотрите результат подготовки и очередь **Отправка ответов**. Можно
   отфильтровать её по аккаунту и набору, поправить текст и увидеть предупреждение о повторе.
   Подготовка сама по себе ничего не публикует.
8. Нажмите **Автокомментирование**: все назначенные аккаунты, один аккаунт,
   отмеченные черновики либо первые N. Аккаунты работают параллельно в отдельных браузерах,
   задачи одного аккаунта — последовательно. Задачи сверх лимита браузеров ждут очереди.
   Для каждого аккаунта окно остаётся открытым на всю задачу. Видимый режим включён
   по умолчанию. При CAPTCHA пройдите проверку в окне в течение трёх минут.
   Для некоторых проверок с вращением изображения или пазлом программа делает локальную
   экспериментальную попытку; если TikTok заменит изображения, возможны до трёх попыток.
   Другие виды требуют ручного прохождения. Работа продолжается
   только после распознанного подтверждения. Если проверка закрылась без подтверждения,
   задача остановится с сообщением; при неопределённой публикации проверьте комментарий вручную.
   Состояние и итог последней задачи каждого аккаунта показаны в очереди.
   Вариант «Все найденные ролики» сначала создаёт недостающие черновики из наборов,
   назначенных выбранным аккаунтам, затем запускает подготовленную очередь.
   Каждую задачу можно отменить отдельно; ошибка одного аккаунта не останавливает другие.
9. Если результат публикации неизвестен, комментарий попадает в **Требует проверки**.
   Проверьте TikTok вручную и отметьте «Опубликовано» или «Не опубликовано».
   Пока это не сделано, автоматический повтор блокируется. После перезапуска
   прерванные операции самостоятельно не возобновляются.

Ручная очередь и конвейер сохранены. Открытие ролика в обычном браузере **не переключает
TikTok-аккаунт**: перед ручной публикацией убедитесь, что вошли в нужный.

### Монитор аккаунтов

Внизу бокового меню показаны все аккаунты. Красный означает отключённую или истёкшую
сессию; жёлтый — ошибку проверки, проблему с прокси либо необходимость свежей проверки;
зелёный — подтверждённую сессию. Ошибка сети не считается подтверждённым отключением.
Работа и пауза отображаются отдельно: сессия аккаунта на паузе может оставаться зелёной.

Проблемные аккаунты стоят сверху. Наведение показывает причину и время проверки,
нажатие открывает «Настроить → Сессия» этого аккаунта. Сначала видны пять строк;
«Все аккаунты» раскрывает остальные в прокручиваемом списке. На узком экране в шапке
показано количество аккаунтов с подтверждённой сессией и общее число аккаунтов.

**Настройки → Монитор аккаунтов**: интервал по умолчанию 15 минут, доступно 1–1440 минут
или отключение автопроверки. Проверки работают на сервере, пока приложение запущено,
даже если его страница закрыта. Они используют общую очередь и ждут текущую задачу
аккаунта; повторная ручная или автоматическая проверка не создаёт дубликат.
Отключение автопроверки прекращает постановку новых проверок.

Подтверждение старше двух интервалов считается устаревшим и отображается жёлтым.
При выключенной автопроверке используется порог 30 минут. Аккаунты без файла сессии
и отмеченные как заблокированные автоматически не проверяются. Обновление списка
в браузере читает локальные результаты и само по себе не обращается к TikTok.

### Ошибки доступа к роликам и состояние очереди

При временной ошибке загрузки ролика приложение фиксирует HTTP-статус основного
документа, итоговый URL, причину и длительность попытки. Для временных сбоев
используется не более трёх попыток с увеличивающейся паузой (учитывается
`Retry-After` с верхним ограничением). Для 401, 403, 404 и 410 повторов нет.
Проверенное региональное ограничение TikTok (10204) не обходится и не повторяется.

Ошибка одного ролика больше не останавливает остальные ролики в очереди:
`video_unavailable` и `comments_disabled` помечаются как пропущенные,
временные ошибки и `region_restricted` оставляют черновик с причиной.
Черновики с подтверждённым `region_restricted` не попадают в массовый
автоматический повтор, пока пользователь не выберет их явно. Для нестабильного
подключения аккаунта действует порог последовательных ошибок навигации
`network_failure_threshold` в `data/settings.json` (по умолчанию 3,
допустимо 1–10). При достижении порога останавливается только этот аккаунт.

Если ответ на отправку невозможно подтвердить, черновик остаётся в состоянии
`review` и требует ручного подтверждения; автоматический повтор блокируется.
В таблицу `drafts` добавлены поля `error_code` и `last_task_id` с
обратной совместимостью со старыми БД. Сводка каждого запуска доступна
через `GET /api/tasks/{id}/summary` и поле `summary` в ответах
`GET /api/tasks` и `GET /api/tasks/{id}`.
Счётчики опубликованных, пропущенных, ошибок, ожидающих проверки и
необработанных вычисляются из записей БД, включая после перезапуска.
Задача с локальными ошибками получает состояние `partial` («с ошибками»).

### Как уменьшаются повторы

Наборы используют общую историю для всех аккаунтов. При подготовке использование текста
фиксируется в транзакции. В первую очередь используются новые варианты, затем менее
использованные и использованные давно. Для spintax проверяется до 100 раскрытий; замена имени
автора не считается новым вариантом формулировки. Небольшой набор распределяется между
аккаунтами по очереди. При исчерпании уникальных формулировок возможны повторы,
которые отмечаются в очереди.

История отправок не исчезает при удалении черновика. Один аккаунт не получает второй
комментарий под уже обработанным роликом. Неопределённые публикации учитываются при
проверке доступного дневного лимита. Для границы дня используется локальное время ПК.

### Обновление старой установки

При первом запуске новой версии создаётся резервная копия прежней БД, настроек и общей
сессии в `data/backups/`. Старые шаблоны переносятся в отдельные наборы с одним вариантом;
их нужно назначить аккаунтам. Старые черновики и отправленные комментарии сохраняются.
Черновику без аккаунта перед автоматической отправкой нужно явно назначить аккаунт.

Для переноса прежнего `data/session/search_state.json` выберите соответствующий аккаунт
и нажмите «Проверить сессию». Только после подтверждения username TikTok сессия получает
персональный файл; прежний файл сохраняется как `legacy_state.migrated.json`.
Если проверка не удалась, исходная сессия остаётся доступной для повторной проверки.
Перезапустите приложение после обновления файлов.

### API и проверки

- `POST /api/accounts/connect`: `{method: "import", data}` или `{method: "login"}`;
  возвращает задачу авторизации без предварительного создания аккаунта.
  `GET /api/tasks/<id>` возвращает результат, включая определённый аккаунт после успеха.
- `/api/text-sets`: наборы и варианты; `PUT /api/text-sets/accounts/<id>` — назначение наборов.
- `/api/accounts/<id>/session`: сведения / отключение; подмаршруты `import`, `login`, `check`.
- `/api/drafts/generate`: `video_ids` (или все «Подходят»), `account_ids`, `text_set_ids`;
  ответ содержит массивы `created` и `skipped` с причинами.
- `/api/tasks/auto-comment`: возвращает `{tasks: [...]}` — отдельную задачу для каждого аккаунта.
- `/api/drafts/<id>/resolve`: `{published: true|false}` — ручная проверка неопределённого результата.
- `/api/settings/execution`: `{browser_limit, search_account_id}`.
- `/api/account-monitor`: компактные состояния всех аккаунтов без cookies и реквизитов прокси.
- `PUT /api/settings/monitor`: `{interval_minutes}`; `0` отключает новые автоматические проверки.

Прежние маршруты подключения используют явно выбранный аккаунт поиска; операции без выбора
возвращают понятную ошибку. Обзор `/api/session` до выбора аккаунта показывает отсутствие подключения.
Подробные схемы доступны в `/docs`. Секретные cookies API не возвращает.

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python tests/e2e_multiaccount.py
```

Браузерный тест использует отдельную БД в `data/test-runs/` и подменяет все обращения
к TikTok. Реальные комментарии не публикуются. В каталоге проверки сохраняются скриншоты.

## Экспорт CSV

- **Ролики → «⬇ CSV»**: лиды с текущими фильтрами и последним ответом по каждому.
- **Очередь → «Отчёт ⬇ CSV»**: отправленные ответы за период (даты можно не указывать).

Файлы в UTF-8 с разделителем `;`: двойным кликом открываются в Excel. В Google Sheets:
Файл → Импорт → Загрузить, разделитель определится сам.

## Структура

```
app/
  main.py               FastAPI: роутеры, /api/stats, /api/logs, статика
  config.py             пути (TTLH_DATA_DIR)
  database.py, models.py, schemas.py
  routers/              accounts, videos, templates, drafts, tasks
  services/
    spintax.py          генератор вариантов
    tasks.py            параллельный планировщик, очереди по аккаунтам
    sessions.py         отдельные cookies и проверка личности
    session_monitor.py  сводка состояния и фоновые проверки аккаунтов
    text_library.py     выбор вариантов, резервирование и история
    logs.py             лог в файл и в БД
  workers/
    tiktok_search.py    Playwright: вход вручную, проверка сессии, поиск (+ CLI)
  static/               index.html + app.js (Tailwind, Vanilla JS)
data/                   app.db, logs/, session/ (не коммитится)
```

Отладка парсера без UI:

```powershell
.venv\Scripts\python -m app.workers.tiktok_search login
.venv\Scripts\python -m app.workers.tiktok_search search "#coffee" --visible
```
